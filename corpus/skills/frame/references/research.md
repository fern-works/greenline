# Research

Frame reads this page when a frame question waits on a fact the repository does not hold. The fact is found here; the decision it informs stays with the owner. A question researched for its own sake, with no change open, gets its cited answer in the reply and writes no file.

Read the sources yourself, or, inside a change, hand the reading to one fresh agent through the harness's delegation and wait for its report before the next round; no agent reads while the conversation goes on. That agent gets the one brief every fresh agent gets, with the question as its extra and frame, with this page, as the skill it works by; it starts no agent of its own, and its report is named for the step the reading serves, as frame's references page says. Its reading is its own: cite its report, and do not record its sources as ones you consulted.

The reading's job:

1. Investigate the question against **primary sources** (official docs, source code, specs, first-party APIs), not a secondary write-up of them. Follow every claim back to the source that owns it.
2. Write the findings to a single Markdown file, citing each claim's source.
3. Save it where the repo already keeps such notes; match the existing convention, and if there is none, it is the change's, as below.

The change's note is a file in its folder, or, when the work splits into tickets, in the research of its plan directory, which the plan step writes. The frame section cites it, with the question, the supported findings, the counterevidence and the limits of the sources. When a fresh agent did the reading, its report in the change's folder is the change's note; where the note belongs in the repository's own home or a plan directory's research, write it there from the report and link the report.
