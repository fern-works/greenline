# Research

Frame reads this page when a frame question waits on a fact the repository does not hold. The fact is found here; the decision it informs stays with the owner. A question researched for its own sake, with no change open, gets its cited answer in the reply and writes no file.

At any round, a fact you can look up yourself, on the web included, you read inline before the question is asked, and you name its source in the frame section. At careful, a question that needs a reading of its own is proposed as research instead: a topic with its node, its source class (papers, the web or code), the question, and what the answer would change. Propose it through the round's channel, as the interview page says, each topic one question the owner accepts or declines, and write it in the frame section as frame's references page gives the topic's form, its accepted line quoting the owner's words before any reading runs. Inside a change, start one fresh agent per accepted topic through the harness's delegation, working by the start `research`, one at a time: wait for each report before the next agent starts, and no agent reads while the conversation goes on. That agent gets the one brief every fresh agent gets, with its topic as its extra and `research` as the skill it works by; it starts no agent of its own, and files its report with `greenline research report`, as frame's references page says. Its reading is its own: cite its report in each question it informs, do not record its sources as ones you consulted, and resume the rounds with the reports. Below careful, with no change open, or where the session has no delegation tool, read the sources yourself and say so in the frame section; a fresh research agent runs only for a stated question at careful.

The reading's job:

1. Investigate the question against **primary sources** (official docs, source code, specs, first-party APIs), not a secondary write-up of them. Follow every claim back to the source that owns it.
2. Write the findings to a single Markdown file, citing each claim's source.
3. Save it where the repo already keeps such notes; match the existing convention, and if there is none, it is the change's, as below.

The change's note is a file in its folder, or, when the work splits into tickets, in the research of its plan directory, which the plan step writes. The frame section cites it, with the question, the supported findings, the counterevidence and the limits of the sources. When a fresh agent did the reading, its report in the change's folder is the change's note; where the note belongs in the repository's own home or a plan directory's research, write it there from the report and link the report.
