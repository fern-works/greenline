# Explain

explain is the start for "how does X work", for an area the work must change that you cannot yet narrate end to end, for the map of a repository's subsystems, and for a page of the atlas reported drifting. An explanation asked for in a question is answered in the reply, traced from the files, and writes nothing.

Greenline's paths and commands for this skill stand on its references page, [references/greenline.md](references/greenline.md): read it when the work lands in the workspace.

Before the first file is traced, read [method.md](method.md): the atlas's mode, the walk, the form, and the atlas's discovery, pages and refresh.

## Handoff

Consumes: the question and the code it names; for the atlas, the repository's tree, entry points, dependency graph and history, or its plan's modules; for a refresh, the pages reported drifting and the commits since each was read
Produces: the explanation in the reply; the candidate subsystems in the reply for the owner's pick; through the change, the atlas's pages, journeys and index
Next: frame, under the mode the owner approves, when the atlas is written or refreshed; otherwise none, the explanation staying in the reply
