# Test-Driven Development

tdd is the habit for the moment a test is written or changed, a change's need for a new test is weighed, or code is built or a bug fixed test-first, at whatever step the work is in, most often build. It writes no record of its own: the tests and the checks it leaves belong to the step that runs, and that step's section names them. The shape of a seam is deep-modules', a bug whose cause is not yet known is diagnose's first, and removing a test is sweep-tests', with its mutation proof: this habit never deletes a test.

Before the first test, read [method.md](method.md): the check a behavior change leaves, discovering the stack, what a good test is, when a new test earns its place, and the loop.
